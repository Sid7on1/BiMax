# Bimax UI Fix List — 2026-09-30

Compiled from Sid's notes (verbatim, Part 1), the `bimax-frontend-review-2026-09-29.md` static source review (Part 2), the "Review Bimax app experience" research session (Parts 3–4), and the "Frontend Feel Engineering" field guide (Part 5). Cursor references and screenshots in the Appendix.

**Guiding direction for all of it:** *"Cursor's restraint, Claude's warmth, ChatGPT's single hero moment — powered by Bimax's better motion engine."*

**Cross-cutting rule (from the review doc):** the design system already documents "no glass on glass" — small controls keep solid fills, only large raised surfaces transmit, and glass veils carry a WCAG contrast table. Items 2, 3, 13, and 14 are therefore **bugs against the documented system, not taste calls** — fix them to match the tokens, don't redesign.

**Working method:** fix one item at a time with the test gates hot (glass contrast tests, design-preview build check, full app suite). Verify each fix instead of eyeballing it. Validate by behavior (task completion, mis-clicks), not by "looks good" — the aesthetic-usability effect makes people under-report friction.

## Part 2 — From the frontend review doc (`bimax-frontend-review-2026-09-29.md`)

### 16. Retune the bouncy preset for menus
The motion review measured menus at 338 ms with ~12.6% overshoot — slow and toy-like for a high-frequency surface (native macOS menus are ~100–150 ms, zero bounce). Cut to ~200–240 ms with ≤8% overshoot; keep the full 338 ms only for large celebratory surfaces. Verify by feel on the real build. (Distinct from #11: that's a stutter bug, this is the tuning being wrong.)

### 17. The "Reduce motion" setting is orphaned
It writes a config key nothing reads — real reduced-motion behavior comes from the OS media query. Either wire it to force quiet render mode or delete it.

### 18. Dead buttons in Settings
The Environment "Open Environment" and ML Alchemist "Measured experiment pipeline" cards look like buttons but have no click handler. Make them plain read-only text or wire them up — they currently read as broken.

### 19. Build a real native app menu
Right now it's Electron's bare default menu bar, so menu-bar explorers never find anything and you lose free ⌘-shortcuts. File/Open project, Edit, View, Window, Help + Trust Center.

### 20. The welcome copy is generic
"Great work starts here" could be any tool — rewrite the headline around verified agent outcomes, which is the actual differentiator.

### 21. Teach the ⌘2 bar at first run
It's the app's core loop and a learned behavior, and right now it's a static hint line. A 10-second interactive moment ("press ⌘2 from anywhere — try it now") beats it.

### 22. Motion needs visual-regression coverage
The bespoke morph system has zero regression safety — extend the existing design-preview harness to cover the morph paths, or the first refactor will silently break the feel.

## Part 3 — Body-language comparison (full research text, as pasted)

> Source note from the research: Bimax is verified from its own code; Anthropic's motion rules come from their published frontend-design guidelines; the rest is from current product reporting plus the apps themselves. Flagged where thinner.

**The four personalities in one line each:**

- **Cursor** — motion is invisible by design. It's a VS Code fork, so panels snap, lists barely animate, Cmd+K pops inline at your cursor. The body language says: *I'm a tool, I will never slow you down.*
- **Claude Desktop** — warm, calm, deliberate. Paper tones, coral accents, the starburst mark, artifacts gliding in from the right. Motion says: *I'm a thoughtful companion, take your time.*
- **ChatGPT Desktop** — minimal everywhere, expressive in exactly one place: the voice orb. Everything else is fast and forgettable. Motion says: *I'm infrastructure, except when I'm talking to you.*
- **Bimax** — engineered and proud of it. Custom spring physics on the compositor, surfaces that grow out of whatever you clicked. Motion says: *look how precisely I move.*

**Head-to-head:**

| | Cursor | Claude Desktop | ChatGPT Desktop | Bimax |
|---|---|---|---|---|
| Philosophy | Speed > delight; keyboard-first | Calm, organic, human | One hero moment, utilitarian rest | Craft as differentiator |
| Timing | ~100–200 ms, near-instant | 100/300/500 ms rule (their published doctrine) | Fast; orb is the only slow thing | 209–338 ms presets |
| Easing | Flat ease-outs, no character | Exponential ease-out in, ease-in out; bounce/elastic explicitly banned ("feels dated") | Subtle springs on buttons only | Physics springs; bouncy preset has ~13% overshoot |
| Signature moment | None — deliberately | Artifacts panel slide-in; animated mark | The pulsing blue voice orb; send→stop button morph | Seeded morph (panels grow from click point) |
| Micro-interactions | Minimal hover states | Restrained; "one orchestrated load beats scattered micro-interactions" | Send button spring-scale on appear | Richest of the four: 4 spring presets, 18 keyframes |
| AI-state expression | Inline diffs, collapsible tool calls — editor-native, feels fast | Streaming + shimmer, warm and unhurried | Voice orb breathes; transcript is the spine | thinking-shimmer, graph-orbit, talk-speak states |
| Accessibility | OS-standard | prefers-reduced-motion respected | Standard | Best of the four: full reduced-motion mode plus a quiet render mode that kills decoration under battery/thermal/memory pressure |
| Interruption | N/A (nothing to interrupt) | Standard | "Morph, don't teleport" is the industry consensus now | Genuinely ahead: rAF driver retargets mid-flight, no geometry tearing |

**The three tensions that matter:**

1. **Bimax's bouncy menus vs. the entire industry.** Anthropic's own doctrine bans bounce/elastic outright, and native macOS menus run ~100–150 ms with zero bounce. Bimax's 338 ms / 13%-overshoot preset on high-frequency menus is the single most "off" choice in its motion system — it reads playful where the product wants to read precise. This is the fix from the last review, and the comparison hardens it.
2. **The hero-orb lesson.** The industry has been retreating from big expressive moments — Siri went full-screen → orb → edge glow, ChatGPT folded voice into the transcript, Gemini collapsed to a pill. ChatGPT keeps exactly one signature (the orb) and starves everything else. Bimax has craft spread evenly everywhere but no single moment as memorable as the orb or the artifacts slide-in. Evenness is a weakness here: users remember one gesture, not a system.
3. **Cursor's lesson for a dev tool.** Cursor proves that for a tool you live in 8 hours a day, invisible motion is a feature — it reads as speed and trustworthiness. Bimax's motion is beautiful but every millisecond of it taxes the "fast tool" perception. The quiet-mode work is the right instinct; the default presets should skew closer to Cursor's restraint for high-frequency actions.

**What Bimax should steal:**

- **From Claude:** the discipline — adopt something like the 100/300/500 rule as law, and kill the bounce on menus. Warmth comes from timing, not overshoot.
- **From ChatGPT:** pick one signature moment (the seeded morph is the candidate — it's the most distinctive thing in the system) and make it the hero, quiet everything else down a notch.
- **From Cursor:** for anything the user triggers 100× a day, motion should be felt as speed, not seen as animation. Snappy (209 ms) should be the default character, not bouncy.

**Verdict:** Bimax's motion engineering is ahead of all three — compositor springs, interruption-safe morphs, quiet mode, none of them document anything at that level. But its motion taste sits behind Claude and ChatGPT: it hasn't yet learned that restraint is what makes the expressive moments land. The engine is the best in the room; the choreography needs an editor.

## Part 4 — Feel-engineering research findings (full text, as pasted)

**Finding 1 — Under 100ms or it feels broken.** Every click and keystroke needs a visible acknowledgement within 100ms, even if the agent's real work takes minutes. 400ms is the flow budget — cross it silently and users don't perceive "slow", they perceive "broken". For Bimax this means optimistic pressed states and streaming progress on everything, always.

**Finding 2 — Clean UI makes your agent's output feel more trustworthy.** This is the wildest one: processing-fluency research (Reber, Schwarz & Winkielman) shows that things which are easy for the brain to process — symmetric, clear, conventional layouts — don't just look prettier, they feel truer. A clean transcript makes Bimax's answers feel more correct. And first impressions lock in at 50ms (Lindgaard), so the first frame carries a halo over everything after.

**Finding 3 — One rare accent, near-black never pure black.** The Von Restorff effect: in a uniform field, the one thing that differs gets noticed and remembered — which is exactly why five accent colors = visual noise. Raycast's trick is using its red as punctuation, almost never. And pure black causes halation and eye strain; premium dark themes are tinted near-blacks (#0B0C0E–#121212) with elevation expressed as lightness steps, built as a separate color system — never an inverted light theme.

**Bimax-specific:** animate every agent state change (pending → running → done). Change blindness is real — users miss silent updates, and animated transitions measurably fix that.

**Two honest caveats:** the famous "400ms" number's exact origin is a bit folklore-adjacent (treat it as a validated budget, not gospel), and the skeleton-vs-spinner studies contradict each other — what actually matters is whether the skeleton matches the final layout's geometry.

## Part 5 — From the "Frontend Feel Engineering" field guide

### 23. Acknowledge every click in under 100 ms
Even when the agent's real work takes minutes — optimistic pressed states and streaming progress on everything. 400 ms is the flow budget; cross it silently and users don't feel "slow", they feel "broken".

### 24. Animate every agent state change (pending → running → done)
Change blindness is real — silent status updates get missed, and animated transitions measurably fix it.

### 25. One rare accent color
Five accents is visual noise — the Von Restorff effect means the one thing that differs gets remembered, so use the accent as punctuation, almost never (Raycast's red trick).

### 26. Near-black, never pure black
Pure black causes halation and eye strain; premium dark themes are tinted near-blacks with elevation expressed as lightness steps.

### 27. Motion discipline: snappy is the default, not bouncy
100–300 ms ladder, ease-out on entrances, faster exits, interruptible springs — and no bounce/elastic anywhere near menus (Anthropic's own frontend doctrine bans it outright). For anything triggered 100× a day, motion should be felt as speed, not seen as animation.

### 28. Pick one signature moment and make it the hero
The industry keeps exactly one memorable gesture and starves the rest (ChatGPT's orb, Claude's artifacts slide-in). Bimax's candidate is the seeded morph — panels growing out of the click point — it's the most distinctive thing in the system. Quiet everything else a notch so it lands.

### 29. Loading states must match final layout geometry
A skeleton that doesn't match the layout it resolves into feels slower than an honest spinner.

### 30. Clean UI is a trust feature
Processing-fluency research: clean, symmetric, conventional layouts don't just look better — they make the agent's answers *feel* more correct. The transcript cleanup is product work, not decoration.

### 31. Lock the color tokens
Near-black four-elevation ladder `#0B0C0E → #111417 → #171B1F → #1D2227`; one coral signal `#FF7168`; body text `#E8E8E8`, never pure white; 3–5% lightness steps between elevations; hairlines before shadows; desaturate the accent in dark mode and reserve it strictly for action. The dark theme is its own tonal system — never an inverted light theme.

### 32. Lock the motion ladder
Press 120 ms ease-out; popover 180–220 ms from trigger origin; panel 240–300 ms, interruptible. Kill the 338 ms / ~13% menu overshoot. Seeded morph is the signature moment; ambient loops stay quiet. Under reduced motion: cross-fade or jump instantly — no geometry animation at all.

### 33. The agent state block is always visible
Current goal, current step, changed files, next action — all four, all the time. Geometry-faithful skeletons only for full surfaces; text progress for smaller modules. Pending → running → done should move the eye once, then settle. Every run ends with a clean summary: changes, checks, risks, next move.

### 34. Controls live next to what they act on
Contextual controls sit beside the selection or output — not in a distant toolbar. Minimum 24×24 pt hit regions on small glyphs (44×44 where touch is plausible). Menus stay shallow; advanced commands live behind search. Teach shortcuts through early wins, never a shortcut dump.

### 35. Command palette is primary, not auxiliary
Full keyboard completeness for every frequent action — keyboard mastery compounds into loyalty.

### 36. Motion grammar: ease-out in, faster out
Entrances ease out and begin immediately; exits run at ~75% of entrance duration and get out of the way.

### 37. One spacing, radius, icon, and type system
Consistency lowers perceptual work — fluency is experienced as quality. Group with proximity first; no card-and-border soup.

### 38. Type rules
Prose lines near 66 characters; tabular numerals for changing metrics; monospace only for code.

### 39. Dense views front-load the top-left
File, action, and status before secondary metadata — scanning goes leftward on text-heavy surfaces.

### 40. Undo-first, not confirm-first
Reversibility preserves speed and control; only interrupt with a confirmation for what's genuinely irreversible.

### 41. Stream the work, design the ending
Visible step progress rides the goal-gradient effect; the completion summary controls what the user remembers about the whole run.

### 42. Never encode status by color alone
Pair every semantic color with a label or icon — color alone fails as a status channel.

### 43. Test both themes with real content
Contrast is contextual — states, accents, borders, and type weight each need theme-specific calibration. The glass-background work must hold in Moonlight *and* Starlight.

### 44. A brief honest "reviewing changes" beat can build trust
On consequential output, a short visible review step increases trust — but keep it rare and honest, never artificial delay as decoration.

### 45. Don't judge fixes by "looks good"
The aesthetic-usability effect makes people forgive and under-report friction — validate by behavior (task completion, mis-clicks), not compliments.

### Product teardowns — what to steal (from the field guide)
- **Linear** — Tight consistency, keyboard-first operation, meaningful motion, undo over interruption. *Steal: speed as brand.*
- **Raycast** — A tiny surface ladder, hairline borders, and a rare red accent that behaves like punctuation. *Steal: restraint as identity.*
- **Arc** — Persistent context in the sidebar; transient work in small, focused surfaces. *Steal: spaces, not pages.*
- **Things 3** — Objects rise, move, and settle only to explain a change in state. *Steal: motion with a job.*
- **Superhuman** — Keyboard mastery, latency obsession, tutorial-level onboarding, and a designed completion state. *Steal: controls as craft.*

### Counterintuitive findings (from the field guide — treat as hypotheses, not rituals)
- **MYTH 01:** More whitespace does not automatically mean more premium. Spacing helps through grouping, not magic luxury dust.
- **MYTH 02:** Skeleton screens can feel slower than spinners. Evidence is mixed — fidelity to the final layout matters more than the loading technique.
- **MYTH 03:** Working memory is closer to four chunks than seven. Miller's seven is routinely oversimplified; Cowan's revision is the design constraint.
- **MYTH 04:** Instant results can feel suspiciously cheap. A brief, honest "reviewing changes" beat may increase trust for consequential output — but artificial delay must stay rare.
- **MYTH 05:** Beauty can hide usability problems. The aesthetic-usability effect makes people forgive friction and report less of it. Watch behavior, not compliments.
- **MYTH 06:** Z-pattern advice is much weaker than F-pattern evidence. Neither should become a universal placement law.

## Appendix A — Cursor references, described deeply (what "like Cursor" means)

**Multi-file tabs (for #8):** Cursor/VS Code put a horizontal tab strip at the very top of the editor area. Each tab shows a file-type icon + filename, a dot when unsaved, and an × that appears on hover. The active tab is full-opacity and visually connected to the editor below; inactive tabs are dimmed. As tabs accumulate they shrink, then the strip scrolls with overflow chevrons. Middle-click closes a tab; right-click gives Close Others / Close to the Right. Beneath the strip, a breadcrumb bar shows folder › file › symbol, each segment clickable. The explorer tree on the left auto-reveals and highlights the active file, so tree and tabs stay in sync — you never lose your place, and going tree → file is one click.

**Find/replace widget (for #9):** Cmd+F in Cursor opens a small floating card anchored to the top-right *inside* the editor, overlapping the text rather than pushing layout. It's one compact rounded card in the editor's own theme: top row is the find input with a live "3 of 12" match counter, up/down chevrons, and toggle icons for case (Aa), whole-word, regex (.*), and find-in-selection; second row is the replace input with replace-one and replace-all buttons. Esc dismisses it and returns focus to the editor. Whatever is typed/selected when you open it pre-fills the find box. The key qualities: floating not docked, same theme tokens as the editor, dismisses with Esc, never a separate window.

**Toggle contract (for #4):** In Cursor's composer, the + (add context) button opens *and* closes the context tray — same button, same spot, plus Esc. There is no separate Done button in the opposite corner.

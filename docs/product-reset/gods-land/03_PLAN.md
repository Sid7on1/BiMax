# God's Land — build plan

**Date: 2026-09-25. Status: Target — the plan, before any code.** Built from the owner's brainstorm (00), the
extensions (01) and the research (02). Each stage ships on its own, names its exit evidence, and stops the plan if the
evidence is not there. Stage order is the owner's "build it" order from 01 §6, corrected by what the research found.

## Shape

```
 bimax-notch (Swift helper, new)            Electron main (existing)                ⌘2 bar (existing)
 ─────────────────────────────              ────────────────────────                ────────────────
 notch panel, glass, motion      JSON        owns the helper's lifecycle             Seed Morph bloom
 hover + drag detection         ◀──────▶     openFilesInBar(files)  ───────────▶     file attached
 drop targets, shelf storage    stdio        thread states → glass state             talk / dictation
 clipboard (with permission)                 approvals, undo journal, spend
 NO model calls, NO engine                   everything that thinks
```

- **Native, because it has to be.** Electron has no notch API (declined upstream, 02 §2), no global drag detection,
  and no Liquid Glass merging. The helper follows the voice helper's pattern exactly: one Swift target built by a
  `build-notch.sh`, macOS 13 minimum with glass on 26+, packaged as an extraResource, spoken to over stdio JSON.
- **The helper never thinks.** Every prompt, tool, diff and undo stays in the ⌘2 Thread (owner, 00 §"Architectural
  Harmony"). The helper renders, captures and stores. That also keeps it inside the code-only product boundary: it
  needs **no** Accessibility, Screen Recording or Input Monitoring for stages 1–5.
- **The seam already exists.** "Edit with Bimax" is `openFilesInBar(files)` in `app/src/main/index.ts` — the path the
  Finder Quick Action (N3) already uses to open the ⌘2 bar with files attached.
- **Budget (owner, 00):** under 20 MB resident and ~0% CPU while idle — event-driven, no timers except the clipboard
  poll in stage 5, which is measured against this budget before it ships.

Motion from 00/01 lands in the stage whose feature needs it (Droplet in 3, Seed Bloom reuses the existing morph,
Evaporation in 6, Pour and Snow globe after 8). Every motion follows the WWDC18 rule: starts from the current value,
inherits velocity, can be grabbed and reversed mid-flight.

## Owner decisions (answered 2026-09-25)

1. **Ghost Paste is dropped** — "the worse and no use". The Input Monitoring question goes with it.
2. **No shortcut.** God's Land opens only when the cursor reaches the notch.
3. **The notch never takes input.** It talks: text, suggestions, tasks, files and folders. Anything that needs the
   person's words drops down as a Droplet and becomes a ⌘2 thread. (This removes the Command Pop / ⌥Space search mode
   of 00; "find by vague memory" in stage 8 becomes suggestions the notch offers, and a search that needs typing
   happens in a ⌘2 thread.)
4. **Reuse DynamicNotchKit and mould it** to our requirements (done in stage 1: `app/native/notch/Vendor`, changes
   listed in its `BIMAX_CHANGES.md`).
5. Still open, for stage 5: whether to ask for the clipboard permission at all.

## What stays out

- No private frameworks (boring.notch's lock-screen trick).
- No hiding windows from screen sharing — not possible since macOS 15 (02 §2); secrets are masked instead.
- No "heavy file" haptics, cursor slow-down or ambient-light sensing — not available to apps (02 §5).
- No GPL code.

## How it is checked against the gates

Every stage passes `08_ACCEPTANCE_GATES.md` "Gates for every product change": a test that fails when its feature is
neutered, typecheck and the packaged app, and a claim that names the build and the measurement. The code-only product
gate is unaffected through stage 8: the helper requests no Accessibility, Screen Recording or Input Monitoring, and
ships no Computer Use component. Decision 1(a) would change that and needs its own gate change.

## Stage 1 — built and installed, 2026-09-25 (`5ae7fbc`, `6b2a759`)

**What exists:** `app/native/notch/main.swift` (the helper) with DynamicNotchKit vendored and moulded
(`Vendor/DynamicNotchKit/BIMAX_CHANGES.md`); `app/src/main/notch.ts` (what it shows, when it speaks, restarts); menu

## Stage 2 — the shelf, built 2026-09-25

**What exists:** `app/src/main/shelf.ts` (the rules), `app/native/notch/Shelf.swift` (drops, drags, cards, Quick
Look, archive drawer), shelf messages routed by `NotchDeck`. Dragging anything toward the notch opens it with a

## Stage 3 — Drop → ⌘2 → deliver, built 2026-09-25

**What exists:** while dragging, the notch offers two zones — **Keep** and **Edit with Bimax**; file cards get "Edit
with Bimax" on right-click. Edit sends the files to the app, which plays the **Droplet** (`native/notch/Droplet.swift`)
to where the ⌘2 bar opens (the same placement `showQuickBar` uses), then opens the bar with the files attached
(`openFilesInBar`, the Finder Quick Action's path). The task started from them is remembered; when it finishes, the
files it made or changed during that turn — read from its undo journal (`filesChangedSince`), never guessed — dock
on the shelf with the task's name and a badge for its completion check: a jewel for passed, a crack for failed, a
caution for "passed after test files changed" (the owner's Prism and Fissure shades). Non-files dropped on Edit are
kept instead, and the notch says so. Reduce Motion skips the Droplet. The bar opens even if the helper never reports
the landing (1.2 s).

**The Droplet, recorded on this Mac** (screen recording at 60 fps, frames read one by one): the lip swells under the
notch → a teardrop stretches on a liquid neck with the file's icon inside → the neck snaps (a one-frame remnant, like
real liquid) → the drop accelerates down → it spreads sideways into the bar's shape and fades. The first recording
showed a black drop vanishing on a dark window; a light glass rim (a second, slightly larger liquid layer) fixed it.

| Exit evidence | Result |
|---|---|
| Files changed by a turn, from the journal (created, replaced, moved-to; not trashed, undone, older or vanished) | `notch.hatchback.test.ts` |
| Finished = completed / failed / time limit, once; not a stop or a question | `notch.deck.test.ts` |
| Edit takes absolute file paths only; the Droplet lands or times out | `notch.deck.test.ts` |
| A task's result is carried onto a card already on the shelf | `shelf.test.ts` |
| Mutants | 7 of 7 caught (one survived first — the trash case — and the test was strengthened) |
| Droplet path, droplet message parsing | `--selftest` (build gate) |
| Suite | jest 3246 passed / 0 failed; app typecheck clean |

**Not verified:** a person dropping a file on Edit in the installed app and seeing the bar open with it; the Droplet
landing exactly on the bar at a remembered bar position; the Hatchback with a real task's changes; the gap between
the splat and the bar appearing (the plan's one-frame bound) — the recording shows the splat, not yet the bar with it.

## Stage 4 — glass states, built 2026-09-25

**What exists:** `app/src/main/glass.ts` decides one state for the notch, most urgent first, each from a signal the
app really has — **ink** (a task needs you), **fissure** (an unseen result failed: turn failed, time limit, or check
failed), **frost** (working, but the record unchanged for 30 s — the summary moves only on real progress), **night**
(a Night Shift task working), **molten** (working), **bubbles** (messages queued, nothing working), **prism** (an
unseen result passed), **water** (quiet). Opening the notch marks results seen; unseen ones fade after 15 min. The
deck arms one timer for the next moment the glass would change on its own (a task crossing 30 s), never a poll.
`app/native/notch/Glass.swift` draws it: at rest a still symbol beside the notch (flame, snowflake, hand, sparkles,
crack, bubbles, moon), open a material behind the words — heat shimmer, ice from the corners with crystal lines, an
ink swirl, a turning spectrum with a glint, a red glow with a hairline crack, rising bubbles, indigo with a twinkling
star. Reduce Motion stops the animation; Reduce Transparency / Increase Contrast draw one solid line instead.

**Not built: Mercury (live streaming).** The app has no per-task streaming signal; a state that guesses is worse than
none. It needs the engine's stream events surfaced first.
